1. INTRODUCTION                                             *zcmp-introduction*

Neovim 0.12 completes on its own. It opens the menu as you type
('autocomplete'), takes a Lua function as a source ('complete'),
fuzzy-matches, ranks and time-slices what the sources answer, draws the
documentation popup, and asks language servers through |vim.lsp.completion|.
What it does not ship is a configuration for any of that.

ZCmp is that layer and nothing more. There is no engine here: no matcher of
its own, no menu drawing, no scoring, no binary to build. What it adds:

- One table, shaped like blink.cmp's, over the options that already do the
  work: 'complete', 'completeopt', 'autocomplete', 'autocompletedelay',
  'omnifunc' and 'shortmess'.
- A path source, which core has none of. It finds where a path token starts
  in the line and leaves the listing to |getcompletion()| -- the trailing
  '/', hidden dotfiles and '~/' expansion included. A relative token
  resolves against the buffer's directory, not the cwd.
- The LSP wired the way core wants it: both delivery paths at once, the
  trigger characters widened so the second one fires, the omnifunc kept out
  of 'complete' until a server is attached, and -- because switching
  |vim.lsp.completion| on is what buys them -- auto-imports, snippet
  expansion and resolved documentation on accept. See |zcmp-lsp|.
- Snippet sessions driven through two functions defaulting to |vim.snippet|,
  so a server's snippet items and any snippet plugin on |vim.snippet| are
  integrated with no adapter, and candidates in the menu from a snippet
  source of your choosing. See |zcmp-snippets|.
- Keymaps that give themselves back: every mapping is buffer-local, and
  every `fallback` runs whatever the key was mapped to before ZCmp attached.
- A kind column coloured apart from the label, re-derived after a
  |:colorscheme|. See |zcmp-appearance|.
- |:ZCmp| status and `:checkhealth zcmp`, which answer the questions a menu
  that came back empty raises. See |zcmp-health|.
- |zcmp.disable()|, which gives every one of the above back exactly as it
  was found.

What it deliberately does not do: command-line completion (that is
'wildoptions', a different mechanism), a signature window that follows the
cursor, ghost text, per-source scoring, or drawing anything.

2. REQUIREMENTS                                             *zcmp-requirements*

- Neovim 0.12.0 or newer
- Optional: zsnip.nvim, which the `snippets` provider points at by default.
  Nothing else requires it; see |zcmp-snippets|.

3. QUICK START                                               *zcmp-quickstart*

>lua
    require('zcmp').setup({
      keymap = { preset = 'enter' },
      sources = { default = { 'lsp', 'path', 'snippets', 'buffer' } },
    })
<
That is the whole of it. The menu opens as you type, ranks paths, buffer
words, snippets and server items together, shows documentation for the
selected one, and <CR> accepts it.

Nothing is wired up until |zcmp.setup()| runs.

4. CONFIGURATION                                           *zcmp-configuration*

                                                                 *zcmp.setup()*
zcmp.setup({opts})

Merges {opts} over the defaults, creates |:ZCmp|, and enables the engine.

>lua
    require('zcmp').setup({
      -- Which buffers zcmp drives.
      enabled = function(bufnr) return vim.bo[bufnr].buftype == '' end,

      keymap = { preset = 'default' },

      sources = {
        default = { 'lsp', 'path', 'snippets', 'buffer' },
        per_filetype = {},   -- filetype -> provider ids
        providers = {},      -- see |zcmp-providers|
      },

      completion = {
        menu = { auto_show = true },           -- 'autocomplete'
        documentation = { auto_show = true },  -- `popup` in 'completeopt'
        list = {
          max_items = nil,                     -- cap for providers with none
          selection = {
            preselect = true,                  -- `preselect` in 'completeopt'
            auto_insert = false,               -- when on, drops `noinsert`
          },
        },
        trigger = { delay_ms = 200 },          -- 'autocompletedelay'
      },

      fuzzy = { enabled = true },              -- `fuzzy` in 'completeopt'

      snippets = {
        preset = 'default',                    -- accepted, never called
        expand = function(body) vim.snippet.expand(body) end,   -- likewise
        active = function(filter) return vim.snippet.active(filter) end,
        jump = function(direction) vim.snippet.jump(direction) end,
      },

      signature = { enabled = false },         -- see |zcmp.show_signature()|
      appearance = { kind_hl = 'Special' },    -- colour of the kind column
    })
<
An unknown key, or a known one of the wrong type, is reported with
|vim.notify()| and otherwise ignored -- the rest of the config still applies.
A table-shaped option handed a scalar keeps its default.

setup() also appends `c` to 'shortmess': with the menu opening on nearly
every keystroke, "match 1 of 9" in the message line is noise.

                                                              *zcmp-preselect*
'autocomplete' forces `noselect` on, and `preselect` in 'completeopt'
overrides it -- but only for items a source *marked* as preselected. ZCmp's
path source marks its first item, and a language server marks its own when it
has an opinion. Core's buffer scanners mark nothing, so a buffer word is not
under the cursor until you select it.

To have <CR> take the first match whatever produced it, bind
|zcmp.select_and_accept()| rather than |zcmp.accept()|; the difference
between the two is exactly this case.

Neovim 0.12.0 has no `preselect` flag at all, so nothing is ever selected
while the menu opens by itself and |zcmp.select_and_accept()| is the only
binding that accepts anything. `:checkhealth zcmp` says so.

5. SOURCES                                                       *zcmp-sources*

A source is an entry in 'complete'. Four providers ship with ZCmp:

    lsp        the omnifunc, plus |vim.lsp.completion| autotrigger
    path       filesystem paths, anchored at the token under the cursor
    snippets   zsnip.complete, expanded by |vim.snippet|
    buffer     core's own scanners: '.', 'w' and 'b'

`sources.default` is both the list and the priority order -- it becomes
'complete' in the order it is written.

>lua
    require('zcmp').setup({
      sources = {
        default = { 'lsp', 'path', 'snippets', 'buffer' },
        per_filetype = {
          markdown = { 'path', 'buffer' },            -- replaces the default
          lua = { inherit_defaults = true, 'mine' },  -- adds to it
        },
        providers = {
          buffer = { max_items = 50 },
          spell = { flags = { 'kspell' } },
        },
      },
    })
<
A provider whose module is missing contributes nothing, and every other
source still resolves; |:ZCmp| status and |zcmp-health| name it.

==============================================================================
6. PROVIDERS                                                   *zcmp-providers*

>lua
    providers = {
      example = {
        name = 'Example',     -- shown by :ZCmp status and :checkhealth zcmp
        flags = { '.', 'w' }, -- literal 'complete' flags
        module = 'my.source', -- a module serving matches
        opts = {},            -- passed verbatim to the module
        max_items = 100,      -- applied as 'complete's own ^{count}
        enabled = true,       -- boolean, or fun(bufnr): boolean
        available = function(bufnr) return true end,
      },
    }
<
A provider needs `flags`, `module`, or both.

`flags` are written into 'complete' as they stand, so anything the option
understands is a provider: `kspell`, `t` for tags, `k{dict}` for a
dictionary. See 'complete'.

The built-in `lsp` and `path` providers take `opts` of their own: >lua
    lsp  = { autotrigger = true, extend_trigger_characters = true },
    path = { max_items = 250 },
<
`extend_trigger_characters` is what widens the server's declared list to
every letter, and so what makes `autotrigger` fire on a plain keyword at all;
turn it off for a server that misbehaves under a widened list. `path`'s cap is
its own rather than `max_items`, because truncating before the items are built
is less work than 'complete's `^{count}` truncating after.

`enabled` is asked once per resolve; `available` is asked per buffer, after
it. The built-in `lsp` provider uses `available` to keep the omnifunc out of
'complete' until a server that answers completion is attached.

A module is a source if it has either of:

    source({opts})            the 'complete' entry to use, as a string
    completefunc({findstart}, {base})
                              a 'complete' function, in which case zcmp
                              writes the entry itself

If it also has `enable({opts})`, that is called once -- with the provider's
`opts` -- the first time the provider joins a buffer's source list, and again
after a later |zcmp.setup()| or |zcmp.reload()|, which offer it the `opts`
they resolved. `source()` must not depend on it having run: `:ZCmp status`
and `:checkhealth zcmp` ask for an entry without starting anything.

Two things a function source has to get right:

- Answer from the live line, not from {base}. {base} is located in the first
  call of a completion cycle and is not re-derived on a
  `refresh = 'always'` re-invocation, so it goes stale as you type.
- Mark the first item `preselect = 1` to have it selected; see
  |zcmp-preselect|.

See |complete-functions| and |complete-items|, and docs/sources.md in the
repository for a worked example.

                                                          *zcmp-start-column*
The reason 'complete' matters more than it looks: a function source picks its
own start column, and different sources in one menu may pick different ones.
A path anchors at `./al`, a snippet trigger at the whole `<div` run, a buffer
word at the keyword -- all in the same menu, each replacing the right text on
accept. |complete()| takes one start column for the entire menu, which is the
constraint this plugin exists to be free of.

7. LSP                                                               *zcmp-lsp*

The `lsp` source is two things at once, because each covers what the other
misses:

- the `o` flag in 'complete' -- the omnifunc -- which merges server items
  into the same ranked menu as everything else, but asks once per completion
  cycle, so typing on through `vim.` narrows nothing;
- |vim.lsp.completion|'s autotrigger, which re-asks per trigger character but
  answers nothing for a plain keyword.

ZCmp widens the server's declared `triggerCharacters` to every letter, which
is what makes the second one fire at all, and puts the declared list back
when the last buffer using that client lets go of it.

Switching |vim.lsp.completion| on is also what buys the parts of LSP
completion that are not a list of words. On accept, core expands a snippet
item through |vim.snippet|, applies the item's `additionalTextEdits` -- the
import statement at the top of the file -- and runs any command it carries.
On selection it asks `completionItem/resolve` and fills the documentation
popup with the answer. None of that happens in a buffer nobody enabled it on,
and enabling it is not the default.

The omnifunc joins 'complete' only once a client answering
`textDocument/completion` is attached, and leaves when the last one detaches.
That is the provider's `available`, and it is why 'complete' in a buffer with
no server has no dead `o` in it.

>lua
    sources = {
      providers = {
        lsp = {
          opts = {
            autotrigger = true,               -- vim.lsp.completion's trigger
            extend_trigger_characters = true, -- widen it to every letter
          },
        },
      },
    }
<
Turn `extend_trigger_characters` off for a server that misbehaves under a
widened list; autotrigger then only fires on the characters it asked for.

|zcmp.get_lsp_capabilities()| exists so a blink.cmp config moves over
unedited. ZCmp completes through core, so it is
|vim.lsp.protocol.make_client_capabilities()| with the override merged in --
a config that never calls it loses nothing.

One default that is doing more than it looks:
`completion.list.selection.auto_insert = false` writes `noinsert` into
'completeopt', which 'autocomplete' ignores but |vim.lsp.completion|'s own
|complete()| call honours. Without it the server's first item is inserted as
you type, `vim.` becomes `vim.F`, and the next keystroke appends to that.

8. SNIPPETS                                                     *zcmp-snippets*

ZCmp does not expand snippets and does not need to: whatever puts the snippet
in the buffer expands it. What ZCmp drives is the session -- jumping tabstops
and clearing a placeholder -- through two functions, which default to core's:

>lua
    snippets = {
      active = function(filter) return vim.snippet.active(filter) end,
      jump = function(direction) vim.snippet.jump(direction) end,
    }
<
So anything that expands through |vim.snippet| is already integrated, with no
adapter and nothing to configure:

- A language server's snippet items. |vim.lsp.completion| expands them with
  |vim.snippet.expand()| on accept -- core's doing, and it happens because
  ZCmp switched |vim.lsp.completion| on. Accept a function from your language
  server and <Tab> walks its arguments.
- Any snippet plugin that expands with |vim.snippet|.

An engine with a session of its own -- LuaSnip -- is those same two
functions:

>lua
    snippets = {
      active = function(filter)
        local luasnip = require('luasnip')
        if filter and filter.direction then
          return luasnip.jumpable(filter.direction)
        end
        return luasnip.in_snippet()
      end,
      jump = function(direction) require('luasnip').jump(direction) end,
    }
<
blink.cmp spells that `snippets.preset = 'luasnip'`. ZCmp has no presets
here: `snippets.preset` and `snippets.expand` are accepted so a blink config
moves over unedited, and |zcmp.setup()| says out loud that neither is called
rather than ignoring them.

The commands that drive all this are |zcmp.snippet_forward()|,
|zcmp.snippet_backward()|, |zcmp.snippet_delete()| and
|zcmp.is_snippet_active()|. A keymap entry naming one is mapped in Select
mode as well as Insert.

                                                        *zcmp-snippet-source*
Expanding a snippet is one thing; offering snippets as completion candidates
is another, and core has no source for it. That is what the `snippets`
provider id is for, and it points at zsnip.nvim's 'complete' source by
default:

>lua
    snippets = {
      name = 'Snippets',
      module = 'zsnip.complete',
      -- ZCmp owns 'complete', so zsnip is told not to append itself to it.
      opts = { complete = false },
    }
<
That one key is the whole of the coordination. Everything else about
snippets — how many are offered, whether they carry documentation — is
configured in zsnip's own `setup()`, where the rest of zsnip is.

It is a default, not a dependency. The provider is a `module` like any other
(see |zcmp-providers|), so any snippet plugin exposing `source()` or
`completefunc()` takes its place under the same id, and dropping `snippets`
from `sources.default` leaves the rest of the menu untouched. If the module
is not installed the provider contributes nothing, every other source still
resolves, and |:ZCmp| status names it.

zsnip is the one ZCmp ships pointed at because it already speaks 'complete':
being a function source, it picks its own start column, so a `<div` trigger
replaces the whole run rather than the keyword at the end of it. See
|zcmp-start-column|.

9. KEYMAPS                                                       *zcmp-keymaps*

Four presets:

    default     <C-y> accepts, <C-n>/<C-p> select, <Tab> jumps a tabstop
    super-tab   <Tab> accepts
    enter       <CR> accepts
    none        nothing is mapped

>lua
    require('zcmp').setup({
      keymap = {
        preset = 'enter',
        ['<Tab>'] = {
          'select_next', 'snippet_forward', 'show_on_keyword', 'fallback',
        },
        ['<S-Tab>'] = { 'select_prev', 'snippet_backward', 'fallback' },
        ['<CR>'] = { 'select_and_accept', 'fallback' },
        ['<BS>'] = { 'snippet_delete', 'fallback' },
        ['<C-j>'] = {},   -- map nothing to this key
      },
    })
<
Each entry is a list of |zcmp-commands|, tried in order until one reports
that it did something. An entry may also be a function, which is handed the
|zcmp-commands| table -- not the module, so |zcmp.reload()| and the rest of
|zcmp-api| are not on it -- and returns whether it handled the key:

>lua
    ['<C-l>'] = {
      function(cmp)
        return cmp.is_documentation_visible() and cmp.hide_documentation()
      end,
      'fallback',
    },
<
                                                              *zcmp-fallback*
`fallback` runs whatever the key was mapped to before ZCmp attached: a
buffer-local mapping, a plugin's global one, or the built-in behaviour of the
key. That is how <Tab> still indents, <CR> still opens a line, and an
autopair plugin still pairs -- ZCmp knows about none of them.

`fallback_to_mappings` is accepted as a synonym.

`fallback` always answers, so it ends the list: a command written after it can
never run, and ZCmp says so once with |vim.notify()|. Write it last.

Every preset but `none` also brings <C-space>, <Up>/<Down>, <C-n>/<C-p>,
<S-Tab> to jump a tabstop back, <C-b>/<C-f> for the documentation popup,
<C-k> for signature help and <C-y> to accept.

Mappings are installed per buffer, and removed again on |zcmp.disable()| --
which also puts back whatever they displaced. A command list containing a
snippet command is mapped in Select mode as well as Insert.

A name that is not one of |zcmp-commands|, and a command written after
`fallback`, are both reported with |vim.notify()|: a key that quietly does
nothing reads as the plugin being broken.

==============================================================================
10. APPEARANCE                                                *zcmp-appearance*

Core draws the menu, and most colourschemes leave |hl-PmenuKind| linked to
|hl-Pmenu| -- so the kind column reads as part of the label. ZCmp sets
`PmenuKind` and `PmenuKindSel` from `appearance.kind_hl` (`Special` by
default), keeping the menu's own background and the selected row's, and
re-derives both after a |:colorscheme| -- including the one a config sets
after |zcmp.setup()| has run.

`appearance.kind_hl = false` leaves the groups alone. |zcmp.disable()| puts
back what was there, captured as a link where it was a link.

'completeitemalign' is core's, and orders the three columns it has.

11. COMMANDS                                                    *zcmp-commands*

What a keymap entry names by string. Each is also a function on the module,
and each answers whether it did anything.

Menu ~
                                                                  *zcmp.show()*
zcmp.show()             Open the menu. False if it is already open, or the
                        editor is not in Insert mode.

                                                       *zcmp.show_on_keyword()*
zcmp.show_on_keyword()  |zcmp.show()|, but only with a keyword before the
                        cursor -- so a <Tab> bound to it still indents.
                        ZCmp's own; blink.cmp has no equivalent.

                                                                 *zcmp.hide()*
                                                               *zcmp.cancel()*
zcmp.hide()             Close the menu, restoring the text as typed.

                                                          *zcmp.select_next()*
                                                          *zcmp.select_prev()*
zcmp.select_next()      Move through the menu. False if it is not open.
zcmp.select_prev()

                                                                *zcmp.accept()*
zcmp.accept({opts})     Accept the selected item. False if nothing is
                        selected -- which is what leaves <CR> free to open a
                        line. `opts.callback` runs once the item has landed.

                                                     *zcmp.select_and_accept()*
zcmp.select_and_accept({opts})
                        Accept the selected item, or the first one if none
                        is selected. See |zcmp-preselect|.

                                                           *zcmp.is_visible()*
                                                      *zcmp.is_menu_visible()*
zcmp.is_visible()       Whether the menu is up.

Snippets ~
                                                      *zcmp.snippet_forward()*
                                                     *zcmp.snippet_backward()*
zcmp.snippet_forward()  Jump a tabstop. False if there is none that way.
zcmp.snippet_backward()

                                                        *zcmp.snippet_delete()*
zcmp.snippet_delete()   Delete the selected placeholder and keep typing in
                        its place. False outside Select mode. ZCmp's own.

                                                    *zcmp.is_snippet_active()*
                                                       *zcmp.snippet_active()*
zcmp.is_snippet_active({filter})
                        As |vim.snippet.active()|.

All four go through `config.snippets`, so another snippet engine is two
functions away: `snippets.active` and `snippets.jump`. See |zcmp-snippets|
for what that integrates with, and what it does not need to.

Documentation ~
                                            *zcmp.scroll_documentation_down()*
                                              *zcmp.scroll_documentation_up()*
zcmp.scroll_documentation_down({count})
zcmp.scroll_documentation_up({count})
                        Scroll the popup where it stands -- it cannot be
                        focused without leaving Insert mode, which dismisses
                        the menu. {count} is lines; a half page by default.

                                                    *zcmp.hide_documentation()*
zcmp.hide_documentation()
                        Close the popup.

                                                    *zcmp.show_documentation()*
zcmp.show_documentation()
                        Nothing: always false. Core opens the popup with the
                        menu and offers no way to ask afterwards;
                        `completion.documentation.auto_show` is the switch.
                        Kept so a blink.cmp keymap moves over unedited.

                                              *zcmp.is_documentation_visible()*
zcmp.is_documentation_visible()

Signature help ~
                                                        *zcmp.show_signature()*
zcmp.show_signature()   |vim.lsp.buf.signature_help()|, if `signature.enabled`
                        is set and a server offers it. ZCmp never asks by
                        itself: there is no window that follows the cursor
                        through an argument list here.

                                                       *zcmp.hide_signature()*
                                                 *zcmp.is_signature_visible()*
zcmp.hide_signature()   Close the floating preview.

12. API                                                              *zcmp-api*

                                                                *zcmp.enable()*
zcmp.enable()           Take over completion: write the options, install the
                        autocmds, attach to every open buffer. Below
                        Neovim 0.12.0 it reports that and wires nothing.

                                                               *zcmp.disable()*
zcmp.disable()          Hand it back. Mappings are removed and what they
                        displaced is put back, buffers get the 'complete'
                        and 'autocomplete' they had, the global options and
                        the two |hl-PmenuKind| groups are restored, and every
                        client ZCmp switched |vim.lsp.completion| on for --
                        and widened the trigger characters of -- is put back
                        as it was.

                                                            *zcmp.is_enabled()*
zcmp.is_enabled()

                                                                *zcmp.reload()*
zcmp.reload()           Re-derive 'complete' in every buffer ZCmp drives,
                        and start any provider module that has arrived
                        since. While disabled it only forgets which
                        modules have started, so that enabling again
                        starts them; it takes no buffer back.

                                                   *zcmp.add_source_provider()*
zcmp.add_source_provider({id}, {provider})
                        Register a provider. It serves nothing until a
                        source list names it. See |zcmp-providers|. Order
                        does not matter: a call before |zcmp.setup()|
                        survives it, and one after re-derives 'complete' in
                        every attached buffer.

                                                   *zcmp.add_filetype_source()*
zcmp.add_filetype_source({filetype}, {ids})
                        Add providers to one filetype's list, on top of
                        `sources.default`. Order-free in the same way.

                                                  *zcmp.get_lsp_capabilities()*
zcmp.get_lsp_capabilities({override})
                        Capabilities to hand a language server. ZCmp
                        completes through core, so these are
                        |vim.lsp.protocol.make_client_capabilities()| with
                        {override} merged in -- there is nothing of ZCmp's
                        own to announce, and a config that never calls this
                        loses nothing.

                                                               *zcmp.version*
zcmp.version            The plugin's version, as a string.

14. HEALTH                                                        *zcmp-health*

`:checkhealth zcmp` answers the questions an empty menu raises: whether the
engine is enabled and its options are still the ones it set, whether the
buffer it was called from is one ZCmp drives, which sources answered for it
and which could not -- a provider whose module is not installed says so by
name -- whether this Neovim is missing a 'completeopt' flag the config asked
for, and whether another completion engine is loaded alongside, which is the
failure that looks like every other failure. It ends with a minimal config
and what to put in a bug report.

==============================================================================
15. COMING FROM BLINK.CMP                                          *zcmp-blink*

The public surface is deliberately blink.cmp's: the same keymap presets and
per-key command lists, the same `sources.default`, `per_filetype` and
`providers`, the same `completion.menu.auto_show`,
`completion.documentation.auto_show` and `completion.list.selection`, the
same `snippets` overrides, and the same function names on the module.

What has no equivalent, and why:

    cmdline.*, term.*     'completeopt' does not apply to the command line;
                          that is 'wildmode' and 'wildoptions'.
    completion.ghost_text `preinsert` in 'completeopt' is close, but requires
                          `fuzzy` to be unset. Not exposed.
    menu.draw.*           Core draws the menu. 'completeitemalign' orders its
                          three columns; `appearance.kind_hl` colours one.
    accept.auto_brackets  An autopair plugin's <CR> still runs, through
                          |zcmp-fallback|.
    provider scoring      Ranking happens inside core, across all sources at
                          once, with no hook in it. `max_items` and
                          `available` are what is left.
    fuzzy.implementation  There is no matcher here to configure or download.

Two behaviours to expect: <CR> accepts only what a source preselected unless
you bind `select_and_accept` (see |zcmp-preselect|), and the menu waits
`completion.trigger.delay_ms` before any source runs.
